# روايات صمت — Silence Novels

منصة ويب احترافية ومستقلة لقراءة ونشر الروايات، بواجهة عربية (RTL) تدعم الروايات بلغات واتجاهات مختلفة (RTL/LTR)، مبنية على **React + Vite + TypeScript + Tailwind CSS** مع **Supabase** للمصادقة وقاعدة البيانات والتخزين.

> هذا المشروع مستقل بالكامل. لا يعتمد على أي مشروع أو قاعدة بيانات سابقة، ولا يحتوي على أي بيانات وهمية أو محتوى جاهز. كل المحتوى يُنشأ من لوحة الكاتب.

## المزايا

**للقرّاء**
- تصفّح وبحث حقيقي بالاسم/المؤلف/التصنيف/الوسوم، مع فلاتر (الأحدث، الأكثر قراءة، آخر تحديث، مكتملة، مستمرة، أبجديًا، حسب التصنيف واللغة).
- صفحة رواية كاملة: الغلاف، العنوان، المؤلف، الوصف، اللغة، التصنيف، الوسوم، الحالة، عدد الفصول، زر البدء/المتابعة، المفضلة، قائمة الفصول.
- قارئ فصول غني: نص، عناوين، صور، صور متحركة (GIF/WebP)، صوت، اقتباسات، فواصل — بالترتيب الذي حدّده الكاتب.
- إعدادات قراءة: حجم الخط، نوع الخط، تباعد الأسطر، الوضع الداكن/الفاتح.
- حفظ موضع القراءة تلقائيًا، نسبة التقدّم، سجل القراءة، المفضلة، متابعة الروايات.
- دعم RTL/LTR تلقائيًا حسب لغة الرواية.

**للكتّاب**
- إنشاء/تعديل رواية (عنوان، مؤلف، وصف، لغة، تصنيف، حالة، غلاف، وسوم).
- محرّر فصول غني (Rich Text) مع تنسيق كامل يُحفظ فعليًا.
- نظام **Blocks** مرتّب: نص، عنوان، صورة، GIF، صوت، اقتباس، فاصل — مع سحب وإفلات لإعادة الترتيب.
- مدير الشخصيات: إضافة/تسمية/تلوين، وتطبيق لون الشخصية على أسمائها داخل المحرّر.
- رفع عدة صور وعدة ملفات صوتية لكل فصل، وتسمية كل مقطع صوتي (الراوي، المطر، موسيقى التوتر…).
- مدير وسائط: أقسام صور/GIF/صوت، رفع، حذف، استبدال، معاينة، إعادة تسمية الصوت، معرفة أي فصل يستخدم الملف، وإعادة استخدامه.
- نشر/إلغاء نشر الفصول والروايات.

**للإدارة**
- لوحة إدارة بإحصائيات، إدارة المستخدمين والأدوار والصلاحيات، إدارة التصنيفات، وإشراف على المحتوى مع فحص آلي للأنماط الممنوعة.

## الإعداد

### 1) إنشاء مشروع Supabase

1. أنشئ مشروعًا جديدًا على [supabase.com](https://supabase.com) (مشروع مستقل خاص بهذا الموقع).
2. من **Project Settings → API** انسخ:
   - `Project URL`
   - `anon public key`

### 2) تنفيذ ملفات الترحيل

نفّذ ملفات `supabase/migrations` بالترتيب من **SQL Editor** في Supabase:

| الملف | الوصف |
| --- | --- |
| `0001_schema.sql` | الجداول + الدوال المساعدة + المشغّلات |
| `0002_rls.sql` | سياسات RLS + منع تصعيد الأدوار |
| `0003_storage.sql` | حاويات التخزين (covers, chapter-media, audio, avatars) + سياساتها |
| `0004_seed.sql` | الأدوار والصلاحيات والتصنيفات الـ16 |
| `0005_functions.sql` | دوال زيادة المشاهدات |

> ملاحظة: بعد أول تسجيل دخول، عيّن نفسك **المالك** يدويًا مرة واحدة:
> ```sql
> update public.profiles set role = 'owner' where id = '<your-user-id>';
> ```
> لا يوجد أي مالك مكتوب داخل الكود — الأدوار تُدار من قاعدة البيانات فقط.

### 3) إعداد التخزين

تُنشئ `0003_storage.sql` الحاويات التالية تلقائيًا مع سياساتها:
- `covers` — أغلفة الروايات
- `chapter-media` — صور الفصول وGIF/WebP المتحركة
- `audio` — المقاطع الصوتية
- `avatars` — صور المستخدمين

المسار المتبع: `{user_id}/{novel_id}/{filename}` — مطابق لسياسات RLS.

### 4) إعداد Google OAuth

1. في [Google Cloud Console](https://console.cloud.google.com) أنشئ **OAuth 2.0 Client ID** (نوع Web).
2. أضف **Authorized redirect URI**:
   ```
   https://<your-project-ref>.supabase.co/auth/v1/callback
   ```
3. في Supabase: **Authentication → Providers → Google**، فعّله وأدخل Client ID و Secret.
4. في **Authentication → URL Configuration** أضف:
   - **Site URL**: رابط موقعك (مثال: `https://your-site.pages.dev`)
   - **Redirect URLs**: `https://your-site.pages.dev/auth/callback` وأيضًا `http://localhost:5173/auth/callback` للتطوير.

> التطبيق يستخدم تدفّق **PKCE** مع مسار مخصّص `/auth/callback` لتفادي حلقات إعادة التوجيه والصفحة البيضاء.

### 5) متغيرات البيئة

انسخ `.env.example` إلى `.env` واملأ القيم:

```bash
cp .env.example .env
```

```env
VITE_SUPABASE_URL=https://xxxxxxxx.supabase.co
VITE_SUPABASE_ANON_KEY=eyJhbGciOiJIUzI1NiIsInR5cCI6...
```

> يمكن أيضًا إدخال الإعدادات وقت التشغيل من صفحة **Setup** التي تظهر تلقائيًا عند غياب الإعدادات — تُحفظ محليًا في المتصفح. هذا يسمح بالنشر دون إعادة بناء.

## النشر

المشروع موقع ثابت (SPA). بعد `npm run build` يُنشر مجلد `dist`.

### توجيه SPA (مهم للروابط النظيفة)

التطبيق يستخدم **BrowserRouter** لروابط نظيفة (`/novel/name`). لكي تعمل هذه الروابط عند فتحها مباشرةً أو تحديث الصفحة، يجب أن يعيد المضيف توجيه كل المسارات إلى `index.html`. أُضيفت ملفات الإعداد جاهزة:

- **Netlify / Cloudflare Pages**: `public/_redirects` → `/*  /index.html  200`
- **Vercel**: `vercel.json` → rewrites إلى `/index.html`
- **مضيفون آخرون**: اضبط «SPA fallback / error document» إلى `index.html`.

> ملاحظة: بعض مضيفات S3 البسيطة لا تدعم SPA fallback، فتعمل الصفحة الرئيسية والتنقّل داخل التطبيق، لكن فتح رابط فرعي مباشرةً قد يفشل. استخدم مضيفًا يدعم إعادة التوجيه (Vercel / Netlify / Cloudflare Pages) لضمان عمل الروابط النظيفة.

### خطوات النشر

1. `npm run build`
2. انشر مجلد `dist` على المضيف.
3. أضف رابط النشر إلى **Redirect URLs** في Supabase (خطوة Google OAuth).

## الأدوار والصلاحيات

| الدور | الصلاحيات |
| --- | --- |
| **المالك (Owner)** | كل الصلاحيات: الروايات، الفصول، الوسائط، التصنيفات، المستخدمون، الإشراف، الإحصائيات. |
| **مشرف (Staff)** | فقط الصلاحيات التي يمنحها المالك (افتراضيًا: الروايات، الفصول، الوسائط، الإشراف، الإحصائيات). |
| **قارئ (Reader)** | القراءة، المفضلة، سجل القراءة، المتابعة. |

قيود مفروضة على مستوى قاعدة البيانات (RLS + مشغّل `prevent_role_escalation`):
- لا يمكن للمشرف تغيير المالك أو حذفه.
- لا يمكن للمشرف ترقية نفسه أو منح نفسه دور المالك.
- لا يمكن تجاوز الصلاحيات الممنوحة.

## سياسة المحتوى

المنصة مخصّصة للمحتوى **النظيف والمحترم**. يُمنع:
- الإباحية، المحتوى الجنسي الصريح، العري الصريح، الوصف الجنسي الفاحش، أي محتوى موجّه للإثارة الجنسية، الألفاظ النابية، تصنيفات/وسوم إباحية.

المسموح: الرومانسية، الحب، المشاعر، الدراما، الحزن، الرعب، العنف القصصي غير الجنسي، المحتوى النفسي/المظلم.

تتضمّن لوحة الإدارة أداة **فحص المحتوى** التي تمرّ على العناوين والأوصاف والفصول بحثًا عن الأنماط الممنوعة، مع إمكانية اعتماد أو إلغاء نشر أو حذف أي رواية.

## الروابط (SEO)

- صفحة الرواية: `/novel/{novel-slug}`
- صفحة الفصل: `/novel/{novel-slug}/chapter/{chapter-slug}`

كل رابط يعمل عند فتحه مباشرةً وعند تحديث الصفحة (SPA fallback).
